# 금융기관 기준 데이터 구축 (주간 회고)

## 목표
금융조회서의 금융기관 주소를 기준 데이터와 비교하기 위해, 금융기관명을 정확한 코드에 연결하는 기준 데이터를 만들었다.

## 고민과 해결

### 1. 회사명 표기가 제각각이다
- **고민:** 같은 회사도 영문, 약칭, 사명 변경 전후 이름으로 다르게 적힌다.
- **해결:** 금융기관 129곳의 `name`과 `aliases` 사전을 만들고, 구 사명도 함께 넣었다. 비교 전에 전각 변환과 공백·특수문자 제거로 정규화하고 정확 일치로 찾았다.
- **결과:** 129개 코드를 모두 포함했고, 서로 다른 회사 간 표기 충돌은 없었다.

### 2. 저축은행이 한 덩어리로 들어 있다
- **고민:** `bank_name`이 전부 "저축은행"이라 은행 구분이 안 됐다. 실제 은행명은 `branch_name` 앞부분에 있었다.
- **해결:** `branch_name`의 첫 단어를 은행명으로 떼어 `○○저축은행`으로 올렸다. 공백이 없는 행은 이미 모은 은행명 목록과 앞부분을 비교하고, 가장 긴 이름을 우선 적용했다. `상상인`과 `상상인플러스`처럼 겹치는 이름은 직접 등록했다.
- **결과:** 저축은행 81곳을 개별 은행으로 나눴다.

### 3. 고유 코드가 바뀌면 안 된다
- **고민:** 저축은행은 고유 코드가 없어 직접 만들어야 했는데, 크롤링 때마다 기준 파일이 갱신되어 추가한 코드가 사라질 수 있었다.
- **해결:** `050_001`처럼 상위 코드에 일련번호를 붙이고, 번호는 별도 파일에 누적 저장했다. 새 은행은 가장 큰 번호 뒤에 추가하고 기존 번호는 바꾸지 않았다.
- **결과:** 은행이 빠지거나 늘어도 기존 번호가 유지되는 것을 샘플 데이터로 확인했다.

### 4. 출처마다 코드 체계가 다르다
- **고민:** 은행은 은행연합회 데이터가 나은데, 금융결제원 같은 고유 코드가 없다.
- **해결:** 은행연합회의 `bank_name`을 정규화해 alias 사전과 맞추고 같은 코드(`039` 등)를 붙였다. 두 출처의 지점을 짝짓기는 어려워서 은행마다 한 출처만 쓰기로 했다.
- **결과:** `한국씨티은행`이 `027`로 매핑되는 것을 확인했다.

### 5. 사명 변경 정보의 신뢰도
- **고민:** 사명 변경은 정리된 자료가 없어 사전에 틀린 정보가 섞일 수 있었다.
- **해결:** 최근 5년 내 변경은 예금보험공사 변경이력과 뉴스로 확인했다. 근거를 못 찾은 구 사명은 뺐다.
- **결과:** SBI저축은행→교보SBI저축은행, 더블저축은행→라인저축은행 등 확인된 변경만 반영했다.

## 오류와 해결

| 오류 | 원인 | 해결 |
|---|---|---|
| 저축은행 분리 전부 실패 | 공백 없는 지점명에 `split(" ")[1]` 사용 | 은행명 목록 앞부분 비교로 변경 |
| JSON 파일 깨짐 | `json.dump`를 두 번 호출 | 딕셔너리를 합쳐 한 번만 저장 |
| 저장한 파일 내용 사라짐 | `"w"` 모드 덮어쓰기로 추정 | OneDrive 버전 기록으로 복구, 저장 전 백업 추가 |

## 배운 점
- 회사명 매칭은 실패한 이름을 모아 사전을 보강하며 정확해진다.
- 포함 비교는 다른 회사가 섞이므로, 정규화 후 정확 일치가 안전하다.
- 파일을 덮어쓰기 전에는 백업한다.
